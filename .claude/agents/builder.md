# 스냅보드와 영상 제작

`CLAUDE.md`, 영상별 BRIEF의 승인 기록, scene-plan과 reference-analysis를 읽는다. `docs/design.md` 3·6장, `docs/video.md` 1–5장, `docs/morion.md` 1–5장을 작업에 맞게 참조한다.

실제 src 자산으로 `snapboard.png`를 먼저 만든다. 장면별 핵심 프레임에 장면 ID·시점을 연결하고, 전환은 시작·끝 상태를 함께 보여준다. 빈 상자나 텍스트 설명만으로 대체하지 않는다. 사용한 자산과 규격·토큰·계산식은 `source-map.md`에 기록한다.

스냅보드를 사용자에게 먼저 보여주고 critic의 검수를 받는다. 실패 항목을 수정한 뒤 통과본에 대해 사람의 두 번째 승인을 받는다. 승인 전 최종 애니메이션 제작·렌더링으로 넘어가지 않는다.

승인 뒤 `source/`에 재현 가능한 제작 소스를 두고 `video.mp4`를 렌더링한다. 사용 도구와 재실행 명령을 `build.md`에 남긴다. 해당 제작 도구의 지침이 있으면 읽되 프로젝트의 기준과 승인 범위를 유지한다. 폰트·이미지 로드 완료 후 캡처하고 실제 렌더 결과의 글자 넘침, 자산 누락, 전환 경계와 마지막 프레임을 확인한다.

화면·부품·자산은 src에서 가져와 감싼다. 원본을 재디자인하지 않는다. 검수 비교 이미지는 제작 자산으로 쓰지 않는다. `source-map.md`에는 값별 docs 출처와 장면·코드 위치, UI별 src 경로·variant, 레퍼런스 항목별 결과 타임코드를 연결한다.

영상과 검수 가능한 프레임을 먼저 제시하고 critic에게 넘긴다. 실패 시 지적한 항목을 수정한다. 승인된 장면 구성을 바꿔야 하면 director에게 돌린다. 렌더에 실패하면 소스를 완성 영상으로 보고하지 않는다.

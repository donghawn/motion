# Make Video

프로젝트 루트의 `CLAUDE.md`를 먼저 읽는다. 아래 모든 작업 경로는 프로젝트 루트 기준이다. 이 스킬은 영상 제작 흐름이며 기준문서 자체를 새로 설계하거나 변경하는 요청에는 적용하지 않는다.

## 시작

이미 받은 답은 재질문하지 않는다. BRIEF에 필요한 질문은 ‘무엇을 보여줄까요?’, ‘몇 초로 만들까요?’, ‘어떤 레퍼런스를 참고할까요?’ 세 가지다. 초보자가 답할 수 있도록 무엇은 기존 제품의 핵심 흐름, 길이는 그 흐름에 맞는 제안값, 레퍼런스는 `references/starling-main.mp4`를 기본 제안한다. 제안한 길이를 사용자 답 없이 확정값으로 기록하지 않는다.

`out/<영상이름>/BRIEF.md`에 목적·문구/메시지·총길이·레퍼런스·출력 기준의 문서 참조·진행 상태·승인 기록을 저장한다. 승인 기록은 실제 사용자 응답과 대상 파일 버전을 포함한다. 기존 폴더가 있으면 내용을 읽고 재개하거나 새 버전으로 구분한다.

## 제작 순서

1. `.claude/agents/art-director.md`를 적용해 `reference-analysis.md`를 만든다. 주 레퍼런스와 보조 역할, 관찰 근거, 채택 요소 목록을 고정한다.
2. `.claude/agents/director.md`를 적용해 `scene-options.md`에 3안을 요약해 보여준다. **승인 1: 사용자가 한 안을 선택한다.** 선택 후 `scene-plan.md`로 구체화한다.
3. `.claude/agents/builder.md`를 적용해 실제 자산으로 `snapboard.png`와 `source-map.md`를 만든다. 스냅보드는 핵심 상태를 한눈에 비교하는 장면별 이미지다. 먼저 보여주고 `.claude/agents/critic.md`로 예비 검수한다. **승인 2: 사용자가 통과한 스냅보드를 승인한다.**
4. builder가 `source/`, `build.md`, `video.mp4`를 만든다. 실제 영상과 확인 프레임을 먼저 보여주고 critic이 최종 검수한다. 판정은 한 줄로 전달하고 상세 근거는 `review.md`에 둔다.

정규 승인은 위 두 번이다. BRIEF 확인은 입력 수집이며 별도의 제작안 승인 절차를 추가하지 않는다. 승인된 내용이 유지되는 수정은 추가 승인 없이 진행한다. 승인된 구성·문구·배치가 달라지면 해당 단계로 돌아간다.

## 참조 경로

- 제품 색·글자·자산 대응: `docs/design.md` 1–6장과 부록.
- 출력·영상 문구·배경·폰·부품: `docs/video.md` 서두와 1–5장.
- 길이·곡선·패턴·읽기·카메라: `docs/morion.md` 1–5장. 후보 상태와 관찰 근거를 함께 읽는다.
- 실제 제품 모습: `src/screens/`, `src/parts/`, `src/assets/`. 목록만 읽지 말고 사용할 화면을 직접 확인한다.

## 게이트

**근거 없는 수치 0개.** 제작에 쓰인 길이·곡선·색·크기는 docs의 해당 장·토큰 또는 허용된 계산으로 추적한다. 총길이는 사용자 BRIEF가 근거다. 장면 시작·끝은 그 안에서 동작·읽기 시간을 합산해 정한다. 문서가 장면별 결정을 허용한 위치·정렬·래퍼 배율·카메라 이동량은 해당 조항과 실제 화면·부품 근거를 source-map에 적으면 허용한다. 단지 임의의 값을 source-map에 적었다고 근거가 생기지는 않는다. 문서에 없는 새 연출 수치는 자동 채택하지 않고 필요한 기준을 사용자에게 묻는다.

**출처 없는 제품 UI 0개.** 화면·부품·상태마다 src 출처를 연결한다. 기존 UI를 감싼 프레임과 별도 영상 헤드라인은 video의 허용 범위에서 구분해 사용한다. 제품에 없는 버튼·아이콘·데이터·기능을 영상 문구로 위장하지 않는다.

**레퍼런스 반영 60% 이상.** 제작 전 고정한 채택 요소 수를 N, 검증 조건을 충족한 요소 수를 M으로 두고 `M/N × 100`으로 계산한다. 항목별 동일 가중치이며 부분 반영은 충족으로 세지 않는다. 항목 ID마다 원본 구간과 결과 장면·타임코드를 연결한다. N이 0이면 미검증이며 통과할 수 없다. 완료 후 분모를 줄이거나 항목을 쪼개지 않는다. 범위 변경이 필요하면 분석과 해당 승인안부터 갱신하고 변경 이유를 남긴다.

스냅보드에서는 정적으로 검증 가능한 항목 집합으로 예비 반영률을 표시하고 동적 항목은 미검증 목록으로 남긴다. 정적 대상이 없으면 비율을 산출하지 않고 그 사유와 예정 동작을 제시한다. 최종 영상은 고정 목록 전체에 대해 위 기준을 충족해야 한다.

검수 단계마다 결과물을 먼저 보여준다. critic의 동일 단계·검사항목이 연속 두 번 실패하면 담당자의 자동 수정도 멈춘다. 사용자에게 실패 증거와 가능한 해결 방향을 묻고 답을 기다린다. 기준문서나 채택 목록을 고쳐 실패를 감추지 않는다.

## 마무리

최종 영상, 제작 소스, 검수 기록의 실제 경로를 제공한다. 통과하지 못했거나 렌더하지 못했다면 그 상태를 분명히 적는다. 이 스킬은 승인 기록·검수 증거를 남기는 절차이며, 문서만 존재한다고 자동 실행이나 검수 강제가 보장되는 것은 아니다.
